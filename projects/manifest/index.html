Shared project standards

  • Every project gets a clear logo, name, status and short explanation above the fold.
  • Every project gets a brief page and a direct path into its working or main site.
  • Mobile presentation must be clean before adding heavy functionality.
  • Demo data stays labeled; private data never belongs in public GitHub files.
  • Large infrastructure upgrades happen only when the prototype actually needs them.
  • Old stable versions are preserved before major replacements.
